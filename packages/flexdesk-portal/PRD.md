# PRD: FlexDesk Portal -- Deployment Readiness

## Introduction

`flexdesk-portal` is a Next.js customer self-service portal within the FlexDesk pnpm + Nx monorepo. It runs on port 3002 and provides link-based access so customers can view invoices, approve quotes, request bookings, track their technician, and pay invoices -- all without creating an account. Access is controlled via signed JWTs generated by the server using `CUSTOMER_PORTAL_SECRET`. The server-side `CustomerPortalController` already provides public endpoints: `GET /customer-portal?token=`, `GET /customer-portal/invoices`, `GET /customer-portal/jobs`, and `POST /customer-portal/invoices/:id/pay`. The portal currently has mostly empty stub files: `approve-quote/index.ts`, `booking-request/index.ts`, `pay-invoice/index.ts` are comment-only placeholders. The `SchedulePage.tsx` is functional and uses `FlexDeskCalendar` from `flexdesk-ui`. The `TrackTechnicianPage.tsx` has a working implementation that fetches from `/api/public/track`. This PRD covers building out all pages, connecting to the backend, adding Stripe payment, and deploying to Vercel.

## Goals

- Build all five customer-facing pages (approve quote, booking request, pay invoice, schedule, track technician) as fully functional, responsive views
- Connect every page to the existing `customer-portal` backend endpoints using token-based auth
- Integrate Stripe Checkout for invoice payment via the server's payment link endpoint
- Ensure responsive design for mobile-first usage (customers access via SMS/email links on phones)
- Handle expired/invalid tokens gracefully with a clear error page
- Support workspace branding (logo, colors) from the portal data response
- Deploy to Vercel with proper environment configuration

### US-P02: Create API client with token extraction from URL

**Description:** As a developer, I want a centralized API client that extracts the portal token from the URL query string and attaches it to all backend requests, so every page can call the customer-portal endpoints without duplicating auth logic.

**Acceptance Criteria:**

- [ ] Create `src/lib/api.ts` with a `createPortalClient(token: string)` function returning an axios instance
- [ ] Base URL from `NEXT_PUBLIC_API_URL` environment variable, defaulting to `http://localhost:3001/api/v1`
- [ ] Attach token as `Authorization: Bearer <token>` header on every request
- [ ] Create `src/hooks/usePortalToken.ts` hook that reads `token` from `useSearchParams()` and memoizes it
- [ ] If token is missing, the hook returns `{ token: null, error: 'Missing access token' }`
- [ ] Create `src/lib/types.ts` re-exporting relevant types from `@service-flex/types` or defining portal-specific ones
- [ ] Typecheck passes

## Non-Goals

- No customer account creation or login (access is token-only via links)
- No real-time WebSocket updates for technician tracking (use polling)
- No in-app chat or messaging with the business
- No estimate editing by the customer (approve/decline only)
- No recurring payment setup
- No multi-language/i18n support (v2)
- No dark mode

## Technical Considerations

- All source files live in `packages/flexdesk-portal/`
- The portal depends on two workspace packages: `flexdesk-ui` (calendar, map components) and `@service-flex/types` (shared TypeScript types)
- The backend `CustomerPortalController` at `/customer-portal` already supports: full portal data, invoices list, single invoice, jobs list, single job, and payment link generation via Stripe
- Token auth uses `CUSTOMER_PORTAL_SECRET` from the server env; tokens are signed JWTs containing `customerId` and `workspaceId` with configurable expiry
- The `TrackTechnicianPage` already imports from `@/modules/api/client/apiClient` and `@/modules/technician/components/JobMap` -- these paths suggest it was originally written for the admin app and needs path adjustments for the portal context
- Stripe integration is server-side: the portal calls `POST /customer-portal/invoices/:id/pay` which returns a Stripe Checkout URL; no client-side Stripe SDK is needed
- Google Maps is required for the Track Technician page; the API key should be set via `NEXT_PUBLIC_GOOGLE_MAPS_KEY`
- The `project.json` Nx config is already set up with dev, build, start, lint, and typecheck targets
- Port 3002 is configured in `package.json` dev script
